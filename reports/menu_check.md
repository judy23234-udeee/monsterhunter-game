# 메뉴 5개 화면 점검 (사냥꾼 선택 · 스킬 트리 · 대장간 · 상점·마을 · 도감)

- 날짜: 2026-11-03
- 1차 점검 → 문제 5개 발견 → 수정 → 2차 점검 (이 문서는 2차 결과 기준, 1차 결과는 4장)
- 환경: 내장 브라우저, `?autotest=1&fps=1` (봇 저장 `mh_autotest_save`, 7단계 클리어 상태), 화면 390×844 · 360×640, DPR 1
- 방법: 각 화면을 열고 (1) 기본 상태 (2) 탭마다 카드 모두 펼침 (3) 스킬 트리 노드 선택 · 직업 변경 확인창을 자동 측정(브라우저에 점검 스크립트만 주입, 게임 코드에 테스트 코드 없음)
  - 14px 미만 글자: 글자를 직접 가진 요소의 계산된 font-size (svg/canvas 그림 안 제외)
  - 48px 미만 터치: button · role=button/tab · input의 실제 크기
  - 잘림: overflow가 걸린 글자 칸의 내용 폭 > 칸 폭, 화면 밖으로 나간 요소, 문서 가로 스크롤
  - 겹침: 버튼끼리(0.5px 초과), 글자끼리(2px 초과) 겹치는 쌍. 화면 위·아래에 붙는 고정 패널(머리 줄, 직업 변경 확인창, 고른 노드 상세)과 그 밑으로 스크롤되는 내용의 겹침은 의도라 뺐다(불투명 배경)
  - 닫기: 맨 위 · 중간 · 맨 끝 스크롤 위치에서 ✕ 버튼이 화면 안에 있고 그 자리를 누르면 ✕가 눌리는지(`elementFromPoint`), 맨 끝에서 아래 닫기 버튼도 같은지
- 스크린샷: `reports/menu_check/` 21장(수정 후), `reports/menu_check/before/` 21장(수정 전). 브라우저 화면 캡처라 JPG.

## 3. 열고 닫기 100회 (누수 · 프레임)

각 화면을 `열기 → 2프레임 → 닫기 → 1프레임`으로 실제 버튼 클릭 100회씩, 5개 화면 합쳐 500회를 **두 번(1000회)** 돌렸다. 수정 전에도 같은 측정을 했고 결과가 같았다(누수 없음).

| 지표 | 시작 | 500회 뒤 | 1000회 뒤 | 판정 |
|---|---|---|---|---|
| DOM 노드 수 | 1549 | 1539 | 1539 | 늘지 않음 |
| canvas 수 | 24 | 24 | 24 | 동일 |
| WebGL 버퍼 만든 수 / 지운 수 | 0 / 0 | 3600 / 3600 | 7200 / 7200 | 1:1 (사냥꾼 미리보기 12개, 대장간 24개를 열 때 만들고 닫을 때 지움) |
| WebGL 텍스처 · 프레임버퍼 · 프로그램 · VAO | 0 | 0 | 0 | 새로 만들지 않음 |
| 닫은 뒤 남은 rAF 루프 | 0회/초 | 0회/초 | 0회/초 | 미리보기 루프가 닫으면 멈춤 |
| 뒤로 가기 기록 길이 | 4 | 4 | 4 | 넣은 칸이 매번 되돌려짐 |
| JS 힙 | 16.5 MB | 17.3 MB | 24.7 MB → **GC 뒤 16.9~17.0 MB** | 쓰레기는 GC로 회수되고 늘지 않음 (+0.5 MB는 아이콘·도감 그림 캐시) |
| 대기 화면 프레임(2초) | 평균 16.68 ms · p95 16.9 · 최대 17.1 | 같음 | 같음 | 60fps 유지 |
| 1회 왕복 | | 평균 50.0 ms · 최대 51.7 ms | | 3프레임 대기만큼. 끊김 없음 |

- 화면을 연 상태의 프레임(1.5초, 수정 전 측정): 5개 화면 모두 평균 16.66~16.68 ms, 최대 17.1 ms. 미리보기 루프는 사냥꾼·대장간·도감에서만 돈다(약 61회/초).
- 힙은 강제 GC를 쓸 수 없어 큰 임시 배열을 만들어 GC를 유도한 뒤 쟀다: 17.0 · 16.9 · 17.0 · 16.9 MB.
- 한계: PC 브라우저 측정이다. 저사양 폰 실기기 프레임은 확인하지 못했다(미확인). 브라우저 창이 가려지면 rAF가 멈추므로 창을 띄운 상태의 값만 넣었다.
